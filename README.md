# Texas2000: סורקים, מזמינים, משלמים

מערכת למסעדות ובתי קפה. על כל שולחן יש ברקוד. הלקוח סורק אותו, מזין שם וטלפון, רואה את התפריט, שולח הזמנה שהצוות מאשר, ובסוף משלם את החלק שלו ומשאיר טיפ. הכול מהטלפון, בלי להוריד אפליקציה ובלי לחכות למלצר.

## מסעדת הדגמה

בהפעלה הראשונה נוצרת מסעדה לא אמיתית בשם **"קפה טקסס"**, עם 20 שולחנות, תפריט מלא ותרחיש "באמצע משמרת":
- **שולחן 1:** חשבון שהמלצר הקליד ידנית.
- **שולחן 2:** שני סועדים עם הזמנות שאושרו.
- **שולחן 5:** הזמנה שממתינה לאישור.
- **שולחן 8:** חשבון ששולם חלקית.
- **שולחן 11:** שולם במלואו ומחכה לשחרור.

| | |
|---|---|
| כניסה | `/login` ← "כניסה לדמו" |
| משתמש | `demo` |
| סיסמה | `demo1234` |

לפני כל הצגה ללקוח אפשר ללחוץ על **"איפוס נתוני הדמו"** בראש המסך כדי לחזור לתרחיש ההתחלתי.

**איך להראות את זה לבעל מסעדה:** פותחים את מסך הצוות על מחשב או טאבלט, ונותנים לו לסרוק ברקוד מהטלפון שלו (דף "ברקודים" או "מסך הלקוח" בתוך שולחן). הוא מזמין, ההזמנה קופצת אצלכם עם צליל, מאשרים, והוא משלם.

## מה יש במערכת

**לקוח** (`/t/<קוד-שולחן>`, נפתח מהברקוד)
- חובה להזין שם וטלפון נייד ישראלי לפני שרואים משהו.
- תפריט לפי קטגוריות, עם סל הזמנה והערה לצוות.
- סטטוס ההזמנות שלי בזמן אמת: ממתינה, אושרה או לא אושרה.
- החשבון של השולחן, כשהפריטים שלי מסומנים.
- אפשרויות תשלום: **רק מה שהזמנתי**, כל היתרה, חלוקה שווה או סכום חופשי.
- טיפ (בלי, 10%, 12%, 15% או סכום אחר) ואמצעי תשלום (Apple Pay, Google Pay, bit או אשראי).

**צוות** (`/staff`, אחרי כניסה)
- **שולחנות:** מפה צבעונית של כל השולחנות (פנוי, יושבים, חשבון פתוח, הזמנה ממתינה, שולם). לחיצה על שולחן מציגה את הסועדים עם הטלפונים שלהם, ההזמנות, החשבון, התשלומים והטיפים, ומאפשרת להוסיף פריט, לסגור חשבון ידנית או לשחרר את השולחן.
- **הזמנות:** תור הזמנות לאישור או לדחייה, עם צליל והתראה על הזמנה חדשה.
- **תפריט:** הוספה, עריכה ומחיקה של פריטים, וסימון "אזל".
- **הגדרות:** שם המקום, הפעלה וכיבוי של הזמנות דרך האפליקציה (למקומות שרוצים רק "לראות חשבון ולשלם"), הוספת שולחנות והחלפת סיסמה.
- **ברקודים:** דף הדפסה עם ברקוד ייחודי לכל שולחן (`/qr`).

**הרשמה:** כל מסעדה פותחת חשבון עם שם משתמש וסיסמה, בוחרת כמה שולחנות יש לה (ברירת מחדל 20) ומקבלת ברקוד לכל שולחן. כל מסעדה רואה רק את הנתונים שלה.

כשהצוות משחרר שולחן, הסועדים מנותקים, כך שהלקוחות הבאים באותו שולחן לא יראו את החשבון של הקודמים.

## הרצה

```bash
npm install
npm start        # http://localhost:3000
npm test
```

| משתנה סביבה | תפקיד |
|---|---|
| `PORT` | פורט (ברירת מחדל 3000) |
| `DB_FILE` | מיקום מסד הנתונים (ברירת מחדל `data/texas2000.db`) |
| `PUBLIC_URL` | הכתובת הציבורית שתוטבע בברקודים, למשל `https://app.example.com` |
| `DEMO_PASSWORD` | סיסמת חשבון הדמו (ברירת מחדל `demo1234`) |
| `SEED_DEMO` | `false` כדי לא ליצור את מסעדת הדמו |

דרוש Node 22.13 ומעלה (משתמש ב-SQLite המובנה של Node).

## מבנה הקוד

```
server.js              הפעלה
src/app.js             חיבור הנתיבים
src/db.js              סכמת מסד הנתונים
src/auth.js            סיסמאות (scrypt), סשנים בעוגייה
src/bills.js           חישובי חשבון, אישור הזמנה
src/seed.js            מסעדת הדמו
src/payments.js        ספק התשלום (כרגע מדומה)
src/routes/customer.js API ללקוח
src/routes/staff.js    API לצוות
src/routes/auth.js     הרשמה וכניסה
public/                המסכים (לקוח, צוות, ברקודים, דף נחיתה)
```

## מה חסר כדי לצאת לשוק

1. **סליקה אמיתית.** `src/payments.js` מדמה תשלום. צריך לחבר ספק סליקה ישראלי (Tranzila, CardCom, Grow/Meshulam, PayPlus) דרך דף התשלום המאובטח שלהם.
2. **אימות טלפון ב-SMS.** כרגע המספר נבדק רק לפי הפורמט.
3. **מדיניות פרטיות.** אוספים שם וטלפון, ולכן צריך מדיניות פרטיות והסכמה לפי חוק הגנת הפרטיות.
4. **חיבור לקופה (POS)** כמו Tabit או Beecomm, למקומות שעובדים עם קופה.
5. **קבלה או חשבונית דיגיטלית.**
6. **אחסון בענן** עם דומיין קבוע, כדי שהברקודים יעבדו מכל מקום.
